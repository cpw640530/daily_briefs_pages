工具一：grok-build-vscode（新项目）

  • 一句话介绍：把 Grok Build CLI 的编码 Agent 能力包上图形界面，并做成 VS Code / Cursor 扩展，同时声称可对接 Codex 与 Claude Code。
  • 分类：Vibe Coding / 编程插件
  • 适合谁：已经在用或想试 Grok Build CLI 的开发者；希望在一个编辑器界面里切换多个 CLI 编码 Agent 的人；需要在 Windows/macOS 桌面端用 GUI 而非纯命令行操作的人。
  • 典型场景：在 VS Code 内直接发起代码生成与重构；把一个项目同时交给 Grok、Codex、Claude Code 会话处理并对比结果；把原本只在终端跑的构建流程搬到桌面 GUI。
  • 核心功能：Grok Build Desktop（Windows、macOS）；Grok Build CLI 的 GUI 封装；面向 VS Code、Cursor 等编辑器的扩展；仓库描述中明确标注"New: Talks to Codex and Claude Code, too"。

  • 支持平台：VS Code、Cursor（描述中为"and more"，未逐一列明）；桌面端 Windows、macOS

工具二：hermes-agent-awesome-plugins（新项目）

  • 一句话介绍：一个可安装的 Hermes Agent 插件包，用来集中管理多家模型提供商的额度、工具卡死控制、推理与迭代预算、会话外观和 RSS 阅读等。
  • 分类：自动化 / Agent 效率工具
  • 适合谁：Hermes Agent 桌面端或 CLI 的重度使用者；同时接多家模型、需要盯住配额与迭代预算的人；希望把额度、内存回顾、会话管理等琐事插件化的人。
  • 典型场景：跨 OpenAI / Anthropic 等提供商的额度统一查看；Agent 调用工具卡住时自动止损；为长任务设定推理与迭代上限避免跑飞；在会话内直接读 RSS。
  • 核心功能：统一的多提供商配额视图；stalled-tool 控制；推理与迭代预算；会话外观与置顶、滚动；opaque composition；memory review；内置 RSS Reader；插件以 SHA 固定，便于复现。
  • GitHub Stars：27
  • 近期新增 Stars：资料未确认
  • 最近更新时间：2026-10-14（pushed_at 2026-10-14T01:09:57Z）
  • 最新版本：资料未确认
  • 开源协议：MIT
  • 支持平台：Hermes 桌面端与 CLI 工作流（JavaScript 实现，具体宿主环境资料未确认）
  • 使用成本：插件本身为 MIT 开源；底层模型 API 费用资料未确认
  • 上手步骤：1）打开 github.com/apoapostolov/hermes-agent-awesome-plugins ；2）确认本地已安装 Hermes Agent 桌面端或 CLI；3）按 README 安装插件包（仓库强调 SHA 固定安装）；4）在 Hermes 中按需启用配额、预算、RSS 等单项插件；5）先用一个非关键会话验证卡死控制与预算上限是否按预期触发。
  • 推荐理由：它解决的是 Agent 使用者最痛的两件事——"额度看不见"和"任务跑飞停不下来"。MIT 协议、当天仍在推送、且把预算与止损做成可插拔模块，思路比再写一个 wrapper 更可持续。
  • 局限与风险：Stars 仅 27，社区验证极少，属"新项目"补位；强绑定 Hermes 生态，不用 Hermes 的人无法受益；27.8 MB 仓库体积对插件包偏大；多提供商 OAuth 与配额读取意味着插件会接触各平台凭据，需审查权限范围；实际可用性未在资料中给出任何用户反馈。
  • 官网/仓库链接：https://github.com/apoapostolov/hermes-agent-awesome-plugins
