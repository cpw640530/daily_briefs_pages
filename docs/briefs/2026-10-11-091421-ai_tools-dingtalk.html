AI工具日报｜2026-10-11

1. 今日推荐结论

今天推荐 agent-canvas-ai-model、extensiondev/skill 和 claude-subagent-editor，分别适合需要可视化设计 Agent 工作流、希望让代码 Agent 获得浏览器扩展开发能力，以及需要图形化管理 Claude 子 Agent 配置的用户。

2. 推荐工具

  • 典型场景：在正式实现前拆分 Agent 角色、绘制任务节点、保存工作流并导出方案。
  • 核心功能：可视化画布、Agent 工作流规划、本地存储、导出选项；项目描述还提到多 Agent、产品设计和视频广告相关场景。

工具二：extensiondev/skill

  • 一句话介绍：面向 Claude Code、Codex、Cursor 等代码 Agent 的跨浏览器扩展开发技能包。
  • 分类：编程插件 / Vibe Coding / 开发者工具
  • 适合谁：希望让代码 Agent 协助开发 Chrome、Edge、Firefox、Safari 或其他 Chromium、Gecko 浏览器扩展的开发者。
  • 典型场景：让代码 Agent 生成浏览器扩展脚手架、处理 Manifest V3、调试跨浏览器兼容问题，以及准备发布材料。
  • 核心功能：提供跨浏览器扩展开发知识和工作流；覆盖 Chrome、Edge、Firefox、Safari、Manifest V3，并标注支持 Claude Code、Codex、Cursor、GitHub Copilot 等 Agent 或开发工具。
  • GitHub Stars：2（截至资料抓取时间）
  • 近期新增 Stars：资料未确认
  • 最近更新时间：2026-10-10
  • 最新版本：资料未确认
  • 开源协议：Apache-2.0
  • 支持平台：依赖所使用的代码 Agent；目标开发平台覆盖 Chrome、Edge、Firefox、Safari 及 Chromium、Gecko 系浏览器。
  • 使用成本：开源项目；Claude Code、Codex、Cursor 等宿主工具的使用成本需单独确认。
  • 上手步骤：访问项目仓库；阅读安装和使用说明；将技能包接入所使用的代码 Agent；用一个小型 Manifest V3 扩展验证生成、调试和打包流程。
  • 推荐理由：它直接补足 Vibe Coding 中浏览器扩展开发的专业上下文，适合把通用代码 Agent 转化为更具体的跨浏览器开发助手。项目最近仍有更新，且采用 Apache-2.0 协议。
  • 局限与风险：当前 Stars 仅为 2，社区验证有限；资料没有确认技能包的完整安装命令、测试覆盖和对各 Agent 版本的兼容范围；生成的扩展仍需人工检查权限、数据访问和商店发布要求。

5. 今日选择建议

  • 编程场景：开发浏览器扩展时优先试用 extensiondev/skill，先让 Agent 生成一个最小 Manifest V3 项目，再人工检查权限、跨浏览器 API 和构建结果。
  • 办公场景：需要设计重复性 AI 流程时，可先用 agent-canvas-ai-model 绘制任务节点和角色分工，再将流程转成具体提示词或自动化脚本。
  • 创作场景：需要管理多个 Claude 子 Agent 进行内容、设计或代码协作时，可试用 claude-subagent-editor，但应先使用不含密钥和敏感路径的测试配置。
